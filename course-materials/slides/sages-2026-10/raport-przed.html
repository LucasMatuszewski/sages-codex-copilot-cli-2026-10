03 - Dane i granice interpretacji

Co wiemy i czego nie ustalamy

  • 01
    Liczba rekordów, nie tożsamościEksport zawiera 10 odpowiedzi przy 11 zaproszonych. Nie ma mapy tożsamości; nie potwierdzamy 10 różnych osób ani jednej osoby, która nie odpowiedziała.
  • 02
    Bazy zależą od pytaniaq12, q14, q16, q18 i q19 mają po 9 odpowiedzi i 1 brak. Większość pytań otwartych ma mniejsze bazy; pełna tabela pokazuje każdy brak.
  • 03
    Brak źródła discoveryNie dostarczono notatek ani transkrypcji spotkania discovery. Nie przypisujemy zespołowi konkretnej architektury, wersji narzędzi, stanu testów ani wypowiedzi ze spotkania.
  • 04
    Dane nie ustalają programu samodzielnieCzterodniowy program, Codex jako główne narzędzie, porównanie Copilot CLI i dzień 4 poświęcony Copilotowi wynikają z zatwierdzonego zamówienia i agendy.
  • 05
    Scalone oczekiwaniaPytania otwarte wskazują ogólnie na praktyczne usprawnienie pracy z oprogramowaniem, kontrolę jakości i powtarzalny sposób pracy z AI. To interpretacja całości; nie publikujemy cytatów ani liczebności tematów.
  • 06
    Nazwy produktów nie są uprawnieniamiq14 i q16 opisują deklaracje. Dostęp do modelu, CLI, chmury i funkcji eksperymentalnych zależy od konta oraz polityki organizacji.
  • 07
    Prywatność małej grupyNie publikujemy rzadkich szczegółowych etykiet, stażu, identyfikatorów, dat odpowiedzi ani powiązań między pytaniami. Nie rekonstruujemy profili uczestników.
  • 08
    Wynik ankiety to punkt wejściaWnioski pomagają wybrać pierwszy krok i pytania kontrolne. Rzeczywiste umiejętności, dostęp i wyniki testów sprawdzamy podczas ćwiczeń.

05 - Środowisko warsztatu

Własny komputer, sprawdzony terminal

ścieżka kursu

Własne środowisko

Zatwierdzona decyzja organizacyjna: Zoom i własne komputery. q06 Windows 9/10 oraz q07 Eclipse 5/10 i IntelliJ 4/10 uzasadniają zachowanie istniejącego edytora.

  • JDK 17 i Maven 3.9.x do jFTP; Git.
  • Node.js 22+ dla narzędzi CLI instalowanych przez npm.
  • Codex CLI i GitHub Copilot CLI: wersja, logowanie, dostęp i zgody.
  • Build z katalogu głównego: mvn -f app/pom.xml verify.
  • Start: java -jar app/launcher/target/jftp-workshop.jar.
  • IDE do czytania i edycji; import wymaga osobnego sprawdzenia.
  • jFTP bez połączenia FTP, na lokalnych danych syntetycznych.
LUB
przy blokadzie

Mniejszy, uczciwy checkpoint

q08: 2/10 odpowiedzi wymagają doprecyzowania możliwości instalacji. Zgłoś konkretny błąd; nie omijaj zasad firmy. Nie planujemy wspólnych VM.

  • Brak GUI: analiza repo i testy headless; jawnie zapisz brak sprawdzenia UI.
  • Brak licencji lub logowania: czytanie kodu, plan i przegląd dostępnego diffu.
  • Brak cloud/integracji: zadanie lokalne i opis dalszego kroku.
  • Pomoc organizacyjna według rzeczywistej blokady, bez zgadywania uprawnień.

Co sprawdzamy przed startem

Wersje JDK/Maven, repozytorium, obie komendy CLI i analiza README bez edycji. Podstawa: zatwierdzone wymagania środowiska oraz q08. Pełna lista przygotowania.

Czego ankieta nie potwierdza

Deklaracja używania narzędzia albo licencji firmowej (q14/q16/q17) nie potwierdza bieżącego logowania, dostępu do sieci, uprawnień administratora ani dostępu do chmury. Sprawdź je, nie wklejając tokenów do notatek ani raportu.

06 - Rekomendacje z podstawą wyboru

Od danych do sposobu prowadzenia

1. Zacząć od podstaw i wspólnego zadania

q03: 7/10 deklaracji początkujących, 3/10 średnio zaawansowanych. Prowadzone ćwiczenie przed dodatkowymi wariantami.

2. Pracować na istniejącym kodzie Java

q05 Java 9/10 i q12 desktop 6/9 wspierają jFTP jako zatwierdzony pierwszy projekt. Nie przygotowujemy gotowej modernizacji za uczestników.

3. Zachować IDE i sprawdzić instalację

q07 Eclipse 5/10, IntelliJ 4/10; q08 potwierdzenie 8/10 i doprecyzowanie 2/10. CLI działa obok edytora, terminal jest podstawą budowania.

4. Zweryfikować oba konta, zamiast zakładać dostęp

q14 Codex 8/9, Copilot 6/9; q16: 9 odpowiedzi, q17 deklaracja firmowa 10/10. Przed labem osobno sprawdź logowanie, plan i politykę każdej funkcji.

5. Porównać agentów na tym samym zadaniu

Zatwierdzona agenda: Codex główny w dniach 1-3, Copilot CLI w porównaniach i w dniu 4. Ten sam kod, AC, granice i dowody wyniku.

6. Planować role i zależności przed edycją

Zatwierdzone moduły 2.3/3.1: małe role, briefy, własność plików i integracja. Wzory w repo są materiałem do adaptacji, nie rozwiązaniem zadania.

7. Wymagać testu i niezależnego review

q18: przegląd kodu 4/9, generowanie testów 3/9; zatwierdzone moduły 2.4/3.2. Sprawdzony test, diff i ręczny scenariusz odpowiedni do Java, zamiast deklaracji agenta.

8. Zostawić powtarzalny standard zespołu

Zatwierdzone moduły 4.1-4.4 oraz scalone ogólne oczekiwania z pytań otwartych: instrukcje repo, skill, rola, granice uprawnień, odbiór wyniku. Bez przypisywania częstości oczekiwaniom.

07 - Do sprawdzenia podczas warsztatu

Pytania kontrolne przed kolejnym krokiem

Instalacja i sprzęt

Czy JDK 17, Maven 3.9.x, Node.js 22+, Git i oba CLI działają? Doprecyzuj blokady z q08: 2 z 10 odpowiedzi nie dają jednoznacznego potwierdzenia.

Sieć i logowanie

Czy zatwierdzona sieć pozwala sklonować publiczne repo, pobrać zależności z Maven Central i zalogować oba CLI? To kontrola wymaganych narzędzi, nie ustalenie z ankiety.

Własny edytor

Czy potrafisz otworzyć źródła i terminal w swoim IDE? q07 wspiera zachowanie Eclipse/IntelliJ; nie zakładamy sprawdzonego importu Maven do każdego IDE.

Zakres zmiany Java

Który mały fragment jFTP albo późniejszego projektu ma AC możliwe do sprawdzenia? Program 1.4/2.1 wymaga własnego PRD przed kodem.

Test i dowód

Jaki test ujawnia problem, jaki opisuje baseline, a czego nie sprawdzono? Program 2.4/3.2 i q18 uzasadniają kontrolę jakości, nie twierdzenie o obecnym pokryciu testami w firmie.

Cloud i integracje

Czy konto pozwala na konkretną funkcję cloud albo repozytorium PR? Program 3.3/4.3 daje lokalny fallback. Jira 4/10 i Bitbucket 3/10 z q09 są kontekstem, nie zgodą na integrację.

Tempo i checkpoint

Czy podstawowe zadanie jest jasne i jaki etap został rzeczywiście zakończony? q03 uzasadnia prowadzone wejście; kolejne dni zaczynamy od realnych plików i testów.

Efekt po warsztacie

Którą instrukcję, rolę, skill lub checklistę można zastosować do własnego zadania? To zatwierdzony cel dnia 4 oraz ogólny wniosek z pytań otwartych, bez rankingu osób.
