Przebieg czterech dni · Główne ćwiczenie · Wszystkie materiały

Kiedy sprawdzać: punkty 01-03 oraz dostęp do materiałów z 06 przed dniem 1. Punkt 04 przed każdą implementacją, 05 przy zmianie projektu i przed kolejnym dniem. W dniach 2-4 sprawdzaj aktualny diff, testy i dostęp do potrzebnych funkcji.

01 / dostęp

Repozytorium, Git i własne IDE

Sprawdź: czy możesz otworzyć publiczne repozytorium kursu, sklonować je i uruchomić git status. Pracuj na własnym komputerze; budowanie i start wykonuj w terminalu, IDE służy do czytania i edycji kodu. Sprawdź dostępny JDK i Maven oraz wymagania oryginalnego jFTP; dla CLI Node.js 22+ oraz Git. W terminalu sprawdź java -version, javac -version i mvn -v. Sklonuj oryginalne jFTP do osobnego katalogu. Polecenie budowania ustal z jego POM i README; zapisz pierwszy błąd, bez gotowej naprawy. Gradle dotyczy tylko późniejszego projektu, jeśli grupa go wybierze.

Gdy nie działa: sprawdź sieć i dostęp do publicznego adresu repozytorium; publiczny clone nie wymaga konta GitHub. Zgłoś blokadę prowadzącemu; nie wklejaj tokenów do materiałów.

02 / Codex i Copilot CLI

Logowanie i uprawnienia

Sprawdź: czy działają polecenia codex i copilot, logowanie, wybór dostępnego modelu oraz analiza README bez edycji. Funkcje i limity zależą od licencji oraz ustawień organizacji.

Gdy nie działa: zapisz, co jest niedostępne. Plan, analiza kodu i przegląd istniejącego diffu pozwalają uczestniczyć nawet wtedy, gdy część funkcji jest zablokowana.

03 / skills

Publiczne umiejętności agenta

Sprawdź: czy masz dostęp do EdukeyTeam/agent-toolbox i czy umiejętności używane pierwszego dnia są widoczne w Twoim środowisku. W razie potrzeby sprawdź aktualną listę poleceniem npx --yes skills@latest add EdukeyTeam/agent-toolbox --list.

Gdy nie działa: korzystaj z materiałów HTML i zanotuj przeszkodę; instalację dokończysz po odblokowaniu dostępu.

04 / źródło wymagań

PRD zmiany uzgodniony z grupą

Sprawdź przed implementacją: czy masz PRD wybranej zmiany Java z kryteriami akceptacji i zakresem poza zmianą. Opcjonalny przykład promptu dla innej aplikacji pokazuje metodę opisu wymagań; nie jest punktem wyjścia ani dokumentacją Twojej zmiany Java.

Gdy nie działa: poproś o uzgodniony zakres przed zleceniem agentowi implementacji. Przykłady z folderu course-materials/ nie są dokumentacją Twojej aplikacji.

05 / środowisko aplikacji

Uruchom projekt, który rozwijasz

Sprawdź: instrukcje, zależności, polecenia uruchomienia i istniejące testy w swoim projekcie. Zapisz rzeczywisty stan projektu i wynik próby uruchomienia. Nie zakładamy wspólnego wyniku testów ani gotowego MVP.

Gdy nie działa: pokaż aktualny błąd, spróbuj go rozpoznać z agentem i wybierz mniejszy fragment pracy. Docker i baza są potrzebne tylko wtedy, gdy wymaga ich przyjęta wersja aplikacji.

06 / materiały

Strony kursu i pełne prompty

Sprawdź: czy otwierają się strona materiałów, slajdy, ćwiczenia i biblioteka promptów. Z każdej strony możesz wrócić do indeksu.

Gdy nie działa: otwieraj materiały z kompletnego folderu kursu lub z opublikowanej strony; pojedynczy skopiowany plik może nie mieć stylów i skryptów.
