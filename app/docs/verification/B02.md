# B02 persistence verification

The persistence foundation uses the real TypeORM and better-sqlite3 stack with explicit migrations and no schema synchronization. The unit-of-work serializes callback-scoped transactions; the store exposes repository operations without returning the EntityManager.

Coverage includes JSON/scalar persistence through close/reopen, exact identity and source-event uniqueness, foreign keys, transaction rollback and queue recovery, callback-scoped store invalidation, queue serialization and close draining, revision compare-and-set including clearing nullable values and missing IDs, and rejection of zero/negative revisions with sanitized constraint errors and no partial records. Migration tests verify first/second run receipts, retained synthetic rows, physical SQLite table/constraint metadata, safe failure diagnostics, and file-backed path rules.

## Manual CLI check

The real `pnpm db:migrate` command ran with `DATABASE_PATH` set to an owned temporary file under `/tmp` and printed `{"appliedMigrations":1}`. A direct SQLite inspection found all three expected tables plus the positive-revision CHECK and named identity/event unique constraints. A synthetic vulnerability was inserted through `openFindingsDatabase`, the unit-of-work was closed, and the same file was reopened through the facade; the loaded title, score `7.5`, and JSON tags matched. The owned temporary directory was removed by the command trap. Evidence and exact helper invocation are in `app/artifacts/B02/13-manual-cli.log`.

## TDD and limitations

The migration behavior Red observed the fresh CLI report `appliedMigrations: 0` where one migration was expected (`app/artifacts/B02/01-migration-red.log`). The rollback Red used valid migrated tables, wrote a vulnerability and identity, then failed on an event foreign key; readback showed the prior writes had not rolled back (`app/artifacts/B02/08-rollback-red.log`). The implementation restored transaction protection. Revision checks were already correct, so the added zero/negative cases are Green evidence rather than an artificial Red.

An initial manual helper attempt failed because TSX compiled an external one-off script as CommonJS with top-level `await`; it did not change application code and its temp database was cleaned. The corrected async-entrypoint probe passed (log `13`). The initial CLI migration suite also exceeded its default timeout before a longer evidence-based bound was set; those harness outcomes remain in logs `02`, `04`, and `09`. No API, server, or browser exists for this persistence-only scope, so those flows were not claimed as tested.
