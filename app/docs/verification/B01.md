This file records the executable foundation and verification evidence for B01. It is not a task-status tracker.

## Package baseline

The direct dependency versions are exact pins in `package.json`; the package manager is pinned to pnpm 12.14.0. Before installation, npm registry metadata confirmed the ADR versions exist and their relevant engine/peer declarations are compatible with Node 24.21.0, Angular 22.2.3, TypeScript 6.0.3, Vitest 5.0.5, and better-sqlite3 12.11.1. Notably, `@angular/compiler-cli@22.2.3` requires TypeScript `>=6.0 <6.1`; `@angular/build@22.2.3` accepts Vitest `^4.0.8 || ^5.0.0`; TypeORM 1.1.2 accepts better-sqlite3 `^12.0.0`; and ngx-quill 31.0.1 accepts Angular 22 and Quill 2.0.3.

The dev dependency `jsdom@30.1.3` satisfies the Angular 22.2.3 schematic's `^30.0.0` test-environment selection and Node 24 engine; Angular's unit-test builder falls back to jsdom when no browser environment is selected. `tslib@2.8.1` is a runtime dependency because the Ionic standalone donor and Angular packages require the tslib helper runtime (`^2.3.0`). Registry metadata reports MIT for jsdom and 0BSD for tslib.

The pinned Ionic Angular standalone starter declares Angular 22.1.7, `@ionic/angular`, Ionicons, RxJS, and tslib; its sidemenu sample adds no package dependency. B01 aligns Angular and CLI/build packages to the accepted 22.2.3 baseline and pins Ionicons 8.0.13, RxJS 7.8.2, Zone.js 0.15.1, and tslib 2.8.1 directly as a compatible runtime dependency. No starter source was generated.

Direct package license metadata matches the ADR: MIT for selected runtime packages, Apache-2.0 for TypeScript/Playwright/RxJS, BSD-3-Clause for Quill, and 0BSD for tslib. Resolved graph and frozen-install results are recorded below.

## Harness behavior

The Vitest projects have disjoint unit and integration include patterns. Unit tests exercise temporary-directory uniqueness, scoped cleanup, and idempotent cleanup. The native integration smoke opens a file-backed SQLite database, creates a test-only table, writes and reads a synthetic value across close/reopen, and removes the temporary directory. Neither test uses `app/.data`.
